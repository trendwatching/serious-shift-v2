# Audit — ingestion, synthesis, innovations, frontend

2026-08-08. Everything below is measured against the live staging deployment and
the two real pipeline runs of the same day (`20260808T081415-ingest-aeb031`,
`20260808T083603-synthesize-01a9e2`), not read off the source.

Severity is about consequence, not effort:

- **S1** a reader sees something wrong, or money is spent for nothing
- **S2** the system degrades silently — correct today, no signal when it stops
- **S3** waste, inconsistency, or a latent trap

Nothing here blocks the demo. The four S1s are all invisible-to-visible-later
problems except D1, which is a real accessibility failure on 51 pages.

---

## A. Ingestion

Evidence: one full run, 353 raw files, 1,356 claims, 21 minutes, $1.45, and
**115 fetch failures**.

| # | Sev | Finding |
|---|-----|---------|
| **A1** | S2 | **The scraper follows non-article URLs.** `SKIP_PATTERNS` in `steps/scraper/content.py` filters by path substring (`privacy`, `tag/`, `#`…) and has no file-extension rule, so `.pdf`, `.jpg` and `.zip` links are queued as articles, fetched, and fail. 23 of the 115 failures are assets — including `BobTagxedoSmall.jpg`. |
| **A2** | S2 | **Three sources produce 74 of the 115 failures**: Charles I. Jones (30), OpenAI (24), Jaron Lanier (20). Jones is an academic index page that is almost entirely PDFs; the other two look like stale selectors. Nothing distinguishes "this source is misconfigured" from "this source had a quiet week". |
| **A3** | S3 | **6 YouTube sources are IP-blocked** and contribute nothing — Reid Hoffman, Yuval Noah Harari, Scott Galloway and three others. The run tells you to set `YOUTUBE_PROXY_URL` or `WEBSHARE_PROXY_*`; neither is set on staging. |
| **A4** | S3 | **70 files are discarded as `file_too_small`** (<1500 bytes) with no aggregate reporting. Some are genuinely short posts; some are nav shells the scraper mistook for articles. Today nobody can tell which. |
| **A5** | S3 | **PDFs are dropped rather than read.** For the academic sources they *are* the content, so the pipeline currently ingests those thinkers' index pages and none of their papers. |

**Not a bug:** 157/353 files "processed" looks alarming and is correct — 124 were
already in the database and skipped *before* paid extraction.

## B. Synthesis

| # | Sev | Finding |
|---|-----|---------|
| **B1** | S1 | **Phase 5 (thinker attribution) is paid for and never seen.** 48 API calls per run produce `proponents`/`skeptics`; the route-scoped fragment strips both, and the `voices` module that would render them is hidden on all four spheres by the visibility matrix. Verified: `proponents` is `None` on every published shift. |
| **B2** | S1 | **Phase 7 (synthesis insights) is paid for and never rendered.** 4 calls per run; `insights` reaches `useDomains` and no component consumes it — the design deleted the insights grid. |
| **B3** | S2 | **`velocity` carries no signal**: `accelerating` on 51 of 51 shifts. It is projected into the view-model and never rendered, so today it is only waste — but it is exactly the kind of field someone later renders in good faith. |
| **B4** | S2 | **A failed publication throws away ~25 minutes of generation.** The gate runs once, at the end. Recovery is `mapgen.cli --export-only`, which is free and worked twice today — but the failure message does not say so, so the reflex is to re-run the whole thing. |
| **B5** | S3 | **`shift_refs` never shrinks**: 636 rows for 306 published shifts. 11 innovation links point at shifts renamed by the last republish. The export warns; nothing reconciles. |
| **B6** | S3 | **Run bookkeeping lies after a recovery.** `--export-only` publishes without opening a `pipeline_runs` row, so the history reads "last synthesize: failed" while the map is fresh and correct. |

## C. Innovations

| # | Sev | Finding |
|---|-----|---------|
| **C1** | S1 | **The pipe is built and nothing is feeding it.** 5 innovations total, newest 2026-08-05. `POST /api/innovations/ingest` is correct — authenticated, idempotent on `source_innovation_id`, rate-limited, 401 on a bad token — but it is a push API owned by the upstream innovations database, and that system is not pushing. Consequence: **1 of 51 key shifts** renders an innovations module. |
| **C2** | S3 | **The route family is split**: reads are `/api/v1/innovations*`, writes and images are `/api/innovations/*`. Every other public surface is `/api/v1`. This is someone else's client, so it is a documentation-and-deprecation job, not a rename. |
| **C3** | S3 | **The classifier's escalation path had never run** before today — four stacked bugs, all on the branch that only fires when the lexical scorer is undecided. With 5 innovations it is still barely exercised. |

## D. Frontend

| # | Sev | Finding |
|---|-----|---------|
| **D1** | S1 | **`--color-ink-num` (#B3AEC0) is 2.16:1 on white** and is the row number on every domain page — 10 failing nodes per page, 4 pages. Well under AA. |
| **D2** | S2 | **The axe pass only visits home, key shift and sub-shift.** The domain page and About have never been checked, which is exactly why D1 survived a contrast gate, a token audit and three sweeps. |
| **D3** | S2 | **4 of 11 `--color-ink-*` tokens are outside the contrast gate.** Two of the uncovered ones are below AA (`ink-tag` 2.44:1, `ink-dot` 3.40:1); both appear unused today, so they are dead tokens or latent failures — nothing distinguishes the two. |

| **D5** | S2 | **Hero art is slug-keyed and generated at build time.** Any republish that renames shifts silently drops all 306 images; they fall back to the sphere gradient, which looks deliberate. Recorded in memory as `hero-art-is-slug-keyed`. |
| **D6** | S3 | **Pointer-dependent copy on desktop**: "Tap to open", "SWIPE FOR SOCIETY", "Scroll ›". |
| **D7** | S3 | **The sub-shift tension band's `-30px` bottom margin assumes a stat band follows it.** When the shift has no stat band it overlaps the peel tabs instead. |

## Plan

Ordered by consequence per unit of work. Each step is independently shippable
and independently verifiable.

### 1 — Correctness a reader can see (~1 hour)

- **D1 + D2 + D3.** Darken `--color-ink-num` to the nearest AA value, extend the
  axe pass to all five page types, and make `check-contrast` iterate *every*
  `--color-ink-*` token rather than a hand-kept list — deleting or fixing the two
  dead ones. The gate is what should have caught this; the fix is to close the
  gate, not just the hole.
- **D7.** Make the tension band's negative margin conditional on a stat band
  actually following it.

*Verify:* axe clean on all five page types at 393 and 1440; contrast gate covers
every ink token.

### 2 — Stop paying for what nobody sees (~2 hours)

- **B1.** Decide `voices` in or out. It is a real feature — which thinkers back
  this shift — that is fully built and switched off. Either unhide it for one
  sphere and stop stripping `proponents` from the fragment, or delete Phase 5 and
  save 48 calls a run. **Recommend: unhide.** The content exists and is good.
- **B2.** Same call for `insights`, cheaper either way (4 calls).
- **B3.** Either make the velocity prompt discriminate or drop the field.

*Verify:* a run's API-call count drops, or a reader can see the output. No third
outcome.

### 3 — Make the pipeline's failures legible (~3 hours)

- **A2 + A4 + A6.** A per-source health line in the run summary: articles found,
  fetched, too-small, failed, claims produced — and a non-zero exit signal when a
  source yields nothing two runs running. This is what turns A1/A2/A3 from
  "someone notices eventually" into "the run tells you".
- **A1.** Add an extension filter to `SKIP_PATTERNS`; removes 23 failures a run.
- **B4.** Make the publication failure message name `--export-only` as the free
  recovery.
- **B6.** Open a `pipeline_runs` row for `--export-only` so the history stops
  lying.

*Verify:* re-run ingest; failures drop from 115 to ~90 and every remaining one is
attributed to a named source.

### 4 — The innovations feature (~half a day, mostly not code)

- **C1** is the one that needs a person, not a patch: the upstream innovations
  database has to start pushing. Everything on this side is ready and proven —
  today's classifier run linked one innovation end to end. Worth confirming who
  owns that producer and whether it is pointed at staging or production.
- **B5 + C3.** Reconcile `shift_refs` after publication: disable links whose
  target is no longer published rather than only warning, and re-run `classify`
  as part of the synthesize stage so renames self-heal.
- **C2.** Document the two prefixes and pick one for v2.

### 5 — Durability (~2 hours)

- **D5.** Make a republish that orphans the art *fail loudly*: have
  `check-heroes` compare the manifest against the published slugs, not just
  against the directory. It is a five-line change and it converts a silent,
  invisible regression into a red build.
- **A5.** Decide whether PDFs are content. If yes, that is its own piece of work
  and the academic sources roughly double their yield.
- **D4.** Re-encode the About images.

## Not doing, and why

- **A3 (YouTube proxy)** needs a paid proxy credential. Flagged for a decision,
  not a fix.
- **B5 sub-shift/timeline counts** are fixed at 5 and 3 by the prompts. That is a
  design decision, not drift.
- **D6 pointer copy** — the design says "Tap"; changing it per input type is a
  content decision, not a bug.
