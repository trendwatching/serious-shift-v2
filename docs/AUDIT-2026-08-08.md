# System audit — 2026-08-08

Measured against the live deployments, today's two real pipeline runs
(`20260808T081415-ingest-aeb031`, `20260808T083603-synthesize-01a9e2`), the
staging database, and GitHub Actions history. Nothing here is read off the
source and assumed.

Severity is consequence, not effort:

- **S1** wrong in production or in the delivery path, or money spent for nothing
- **S2** correct today, and nothing signals when it stops
- **S3** waste, inconsistency, or a latent trap

**33 findings. 9 are S1.** The three that matter most are at the top.

## 0. The three that matter most

### E1 — Production is running the old site (S1)

`www.seriousshift.ai` serves the **pre-rebuild Next.js app**: `/_next/static/…`
bundles, title *"Serious Shi(f)t — AGI Consumer Intelligence"*. None of this
work is public.

The production backend is worse — it is `Online` and answers **404 on every
route**, including `/`, `/robots.txt` and `/api/v1/map`. It has no map document
and serves no SPA. The site people can actually visit is a separate `frontend`
Railway service holding the old build, which exists in `dev` and `production`
with **no config file** and is invisible to `railway.*.json`.

Staging is the only working environment. The cutover is entirely pending and
`docs/PRODUCTION-CUTOVER.md` has not been executed.

### C1 — CI has been red all day, on every push (S1)

Four pushes today, four `frontend` workflow failures. I verified everything
locally each time and never opened Actions. Three tests fail:

- **Two homepage visual snapshots** (390×844, 393×852). The baselines are
  generated on macOS and CI runs Ubuntu, so font rasterisation differs by more
  than `maxDiffPixelRatio: 0.015`. This can never pass — the test is
  structurally broken, not flaky.
- **`a route change lands at the top, and a nav anchor lands on its section`** —
  a real bug, below.

`governance` passes. `backend`, `db` and `pipeline` are path-filtered and did not
run on the frontend-only pushes.

### F1 — Five of the six nav rows land in the wrong place (S1)

Clicking **Services** in the nav lands **330–570px above** `#services`, in the
middle of the previous section — and the distance differs run to run (CI
measured 333.9 and 571.9 on consecutive runs).

`ScrollManager` scrolls in `useLayoutEffect`, which fires before any image has
loaded. The About page's section images are `<img class="h-auto w-full">` with
**no `width`, `height` or `aspect-ratio`**, so they occupy zero height at that
moment and then shove the target down as they arrive. Five of six nav rows are
`/about#section`, so five of six are affected. It passes on a fast local machine
by luck, which is exactly why only CI caught it.

## Plan

Ordered by consequence. Each step is independently shippable.

### Step A — Unbreak the delivery path — **DONE 2026-08-08**

CI is green for the first time today. All four nav anchors rest at 96px — their
`scroll-mt-24` — on the deployed site under a throttled network. Snapshot
baselines are per-platform and both sets pass in their own renderer.

1. ~~**C2.**~~ `snapshotPathTemplate` had been overridden to drop `{platform}`;
   restored, Linux baselines generated in the CI container via
   `npm run test:e2e:linux`. The homepage orbs run infinite keyframes that
   `animations: 'disabled'` cannot rewind, so they are pinned to time zero;
   1.5% then covers same-renderer font jitter with an order of magnitude of
   headroom.
2. ~~**F1 + F2.**~~ Every image carries its intrinsic size, which took the drift
   from 330–570px to 17px; the remaining 17 was the webfont swap, so the scroll
   now settles after `document.fonts.ready` and abandons the correction the
   moment the reader scrolls.
3. ~~Re-run CI.~~ Green.

### Step B — Decide production (~1 day, mostly decisions)

4. **E1.** Execute `docs/PRODUCTION-CUTOVER.md`: point the production backend at
   the new build, publish a map into the production database, and retire the
   `frontend` service — or consciously decide staging stays the demo surface.
5. **E3.** Confirm and document the Postgres backup policy.

### Step C — Stop paying for what nobody sees (~2 hours)

6. **S1, S2, S3.** Voices, insights, velocity: turn on or delete. ~52 API calls a
   run either way. My recommendation is still to unhide `voices` — the content
   exists, is good, and is the only place the thinker corpus surfaces to a reader.
   **STILL OPEN — this is a product decision, not a fix.**

### Step D — Make failure legible — **DONE 2026-08-09**

7. ~~**I2 + I4 + I6.**~~ The run summary carries a per-source table — found,
   fetched, too small, failed, claims — sorted worst first, and every figure in
   it is derived from what the run already recorded rather than from a parallel
   tally. A parallel tally is how `Errors: 72` came to sit beside a query
   returning 173; both were right, and the label said neither, so the stage
   summaries now name their stage. A source silent for two consecutive runs
   escalates, which the run-wide check never did — it only fires when *every*
   source is silent, so one dead feed hid behind forty healthy ones.
8. ~~**I1.**~~ Extension filter reads the URL path, so a query string can neither
   invent an extension nor hide one. `.pdf` is deliberately excluded so I5 stays
   visible.
9. ~~**S4 + S6.**~~ The failure message says the generation is intact and names
   the free `--export-only` recovery. `--export-only` opens a run row under a new
   `export` stage — not `synthesize`, which would drag every cost-per-run average
   toward zero.

### Step E — Durability — **mostly done 2026-08-09**

10. ~~**F5.**~~ Not five lines, and not in `check-heroes`: the build has no
    database, so its manifest and its directory both come from the same
    generator run and agree by construction. The backend has both halves and now
    warns on every map refresh when a published shift has no poster on disk —
    which is the case that matters, because the weekly cron republishes into a
    container nobody redeployed and no script runs at all. `preflight-origin.mjs`
    checks the same thing at cutover.
11. ~~**S5.**~~ `shift_refs` is reconciled at publication: stale refs that nothing
    points at are dropped (365 of 370), refs anything points at stay immortal.
    The check is `NOT EXISTS any link` — the FK is ON DELETE CASCADE and a
    disabled link is an editor's veto whose tombstone must survive. The
    `classify`-after-publication half was already in place.
12. ~~**D1.**~~ Decided and written down in
    [`DATA-RETENTION-AND-BACKUP.md`](DATA-RETENTION-AND-BACKUP.md): no window on
    `claims`/`sources`/`predictions`, because a prediction is only resolvable
    months after it is made and that history is what credibility is computed
    from. Review trigger at 20 GB.
13. ~~**C3.**~~ Already in CI — `cargo-audit` via `scripts/audit.py`.
    ~~**F3.**~~ `script-src 'unsafe-inline'` dropped. ~~**F4.**~~ About images
    re-encoded, 644 KB → 493 KB. ~~**F6.**~~ Dead exports deleted — three of the
    six named had come back into use since the audit (`useNavigate`, `quoted`,
    and `LINKEDIN_URL` via `SOCIALS`), so only the genuinely unreferenced ones
    went.

**E3.** The backup policy is written up in
[`DATA-RETENTION-AND-BACKUP.md`](DATA-RETENTION-AND-BACKUP.md). Railway's volume
backup schedule is not exposed by the CLI and still needs confirming in the
